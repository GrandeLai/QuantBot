# 日内盈利证据与独立验证

当前流程是：固定开发候选 → 核对机会与成本 → 验证数据证据 → 重算开发资格 → 冻结独立验证 → 一次性读取与回放 → 重新核验结果。两市场分别评估，全部复用现有撮合、账本、止盈止损与统计门槛。

**本模块不签发模拟盘或实盘授权。** 独立研究合格还需要来源真实性核验、原市场正式准出政策和绑定策略的执行适配验收。合成数据只能验证工程通路，不能获得策略资格。已有日线加密准出不能移作日内准出。

## 机会与成本

```sh
quantbot intraday-study diagnose --attribution attribution.json --output diagnostics.json
```

读取已冻结的 `attribution → study → freeze → protocol` 引用和逐笔回放，重新核对完整持仓周期及现金、成本、数量。这个入口不打开原始行情，不重新运行策略。

报告包含每个市场、候选、窗口、成本和延迟的净损益、记录成本加回贡献、成本侵蚀、盈亏平衡成本、完整周期和固定分组。原研究源码与本轮分析器源码分别记录，不能把新的分析器身份当作原回放已重新执行。

同标的同信号时点的候选/对照可以配对；未配对的盈利对照单列。冷却、风险和仓位状态会改变后续路径，因此这些差异不能直接认定为过滤条件的因果收益。多个独立窗口的现金损益合计不是跨期复利收益，记录成本加回也不是零费用重跑。

## 分钟数据证据

```sh
quantbot intraday-study check-evidence --protocol PROTOCOL.json \
  --data-manifest data-manifest.json --catalog study/catalog-completed.json \
  --output evidence-report.json
```

历史政策已归档时可传 `--policy-snapshots policy-snapshots.json`，只支持已有严格政策映射。

检查会在读取行情前追加开发曝光记录，读取失败也保留。`--catalog` 用于承接最近的完整研究账本，必须是方案 `prior_catalog` 的连续后继；省略时沿用方案中的账本。报告返回新的 `catalog` 文件引用，后续独立验证请求必须承接它，才能识别本次已查看的区间。缺行情市场不记录虚假的价格读取。

数据清单每个市场的可选 `evidence` 引用指向证据包，必须绑定市场、标的、原始价口径、完整范围和行情哈希。证据包另外绑定三份文件：

- `historical_availability`：文档级来源，以及每根 OHLCV 的可得时点和观察时点；完整性、数值和决策截止时间均校验。
- `corporate_actions`：逐会话、逐标的覆盖声明与结构化公司行动，检验原始价口径及历史可得时点。
- `execution_costs`：逐会话、逐标的的费用、点差、滑点、冲击和延迟观测，不能超出冻结基础成本场景能覆盖的范围。

准确字段和时间约束见命令结果中的 `required_schema`。检查分为行情完整性、历史可得性、公司行动、执行成本和保护范围；美股缺行情继续显示缺口。

日内回放支持证据包中有完整详情、开盘前历史可得时点及逐标的/会话覆盖的普通 USD 现金分红和拆股。研究、独立验证和归因共用处理：

- 仅在生效日开盘前整个账户空仓且无待单时支持；前一日部分成交留下的持仓或订单会在处理当日新价格前报错，不能静默重置。
- 拆股在生效日将此前已完成会话的收盘与 ATR 波幅除以比例、历史同槽成交量及上一根成交量乘以比例；当前原始行情与整股撮合保持原单位。未来行动不会改变过去信号。
- 空仓现金分红不产生收入或应收款；原始除息缺口保留并进入之后的 ATR。缺少前一完整会话收盘、金额达到该收盘价的 25%、特殊分配、非 USD、缺详情、迟发或同标的同日多项行动继续拒绝。
- 执行冻结绑定证据包与嵌套行动文件的摘要和规范化行动；研究、独立验证、归因在读取价格前拒绝行动文件篡改，并在结束时复验。旧冻结不能直接借新代码消费未绑定的非空行动，须重新冻结。

`freeze` 在读取开发价格前保存 `catalog-accessed-<market>.json`，行情或公司行动语义检查失败也保留曝光；只有全部冻结步骤成功才生成 `execution-freeze.json`。后续操作须沿最新访问账本继续，不能把失败读过的数据重新当成未曝光数据。完整性与合成回归只证明本地处理一致，不能证明行情来源真实性、美股盈利或交易准入。

`consistency_verified` 表示文件绑定与内部约束通过；真实历史声明完整且当前执行兼容时可得到 `evidence_verified`，但这些校验不能独立认证数据提供方。`authenticity_verified` 与正式准入另外记录。手填 PIT 标记、来源字符串、哈希或合成数据均不能独自获得交易资格。成本观测符合内部约束，也不等于真实成交回执、未来尾部成本或容量验证。

## 独立验证

```sh
quantbot intraday-study validate-prepare --protocol PROTOCOL.json \
  --study study/report.json --request validation-request.json --output independent-plan
quantbot intraday-study validate-run --freeze independent-plan/validation-freeze.json \
  --output independent-run
quantbot intraday-study validate-assess --freeze independent-plan/validation-freeze.json \
  --result independent-run/validation-report.json
```

请求格式为 `version=1`、`mode=research`、`selections` 数组，每市场最多明确选择一个候选；选择项包含 `market`、`candidate_id`、`range`（包含预热）、`windows` 和证据包路径 `evidence`。窗口端点沿用研究协议日期规则。没有候选时可以传空数组，保存阻断结果，不会读取新的价格。

若开发完成后又进行过数据检查，设置请求顶层 `catalog` 为检查报告返回的 `{path, sha256}` 引用；它必须是该开发完成账本的连续后继。已读区间会因此被拒绝作为独立验证。文件链没有全局登记服务，操作者须保留并传递最新链；这个约束不能证明其他目录或系统从未读取数据。

准备阶段从开发回放重新计算完整数值门槛和累计 Holm 校正，不直接信任排名或 `numeric_screen_passed`。对独立窗口检查既有曝光、预热、保护区和证据元数据；该阶段不打开独立行情。通过后冻结原候选定义、风控、撮合、统计、代码、请求、数据及证据引用。

一次性登记保存在开发研究目录下的 `independent-validations`。执行必须先登记访问再读取价格，成本/时点证据不符和执行失败都保留曝光记录；不能通过换输出目录、复制冻结文件或重新准备相同验证来重置次数。报告按冻结窗口和全部成本、延迟场景运行候选及对照，重新核对账户。评估入口从绑定回放和证据重新计算资格，不能接收游离的 `passed=true`。

日终审计从委托受理、部分成交、完成成交和撤单事件重建未完成订单，不能仅凭汇总里的待单数为零通过；隔夜撤单也不能消除前一日的残单问题。

开发源码与当前源码不同时，真实研究需先重跑开发验证；保留旧研究供成本诊断不能替代新代码的开发资格。累计登记仅覆盖已纳入该研究账本与登记目录的历史，不能证明人工在其他目录或系统从未看过该数据；迁移时须一并保留整条证据链。

`strategy_qualified` 是本模块的独立研究资格；来源认证、正式市场准出、券商模拟授权与实盘授权是不同字段。候选未达标、数据缺失、工程合成验证或交易适配尚未验收，都不会打开交易。

## 当前研究边界

原封存留出继续保护，已暴露的开发窗口不能重新命名为独立验证。本轮保留止损 3%、止盈 6%、更紧 ATR、单日亏损 2%、回撤 5% 和原统计/准出要求。当前仍需要合格的真实候选、完整美股分钟与时点证据，以及真实执行成本证据，才能推进后续阶段。
