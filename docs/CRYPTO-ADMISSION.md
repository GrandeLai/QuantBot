# 加密现货分级准出

2026-10-22 冻结首版标准 `crypto_spot_v1`。顺序为：预登记研究 → 独立回测准出 → OKX 模拟盘前向验证 → 小额实盘准备。当前执行阶段仍是回测。

这些数字是本项目的初始工程准出标准，不是行业统一标准，也不保证未来收益。不得为了让已看过的结果通过而降低门槛；改策略、模型、提示词或风险限额后，创建新版本并使用未暴露的最终留出。多次试验的历史必须保留。

## 回测进入 OKX 模拟盘的门槛

以下条件全部满足才标记 `backtest_passed=true`：

| 项目 | 要求 |
|---|---|
| 范围 | BTC/USDT、ETH/USDT 现货多头，AI 候选胜出；不使用杠杆 |
| 时间 | 研究覆盖至少 180 个自然日；独立留出至少 60 日，不含指标预热；至少 3 个开发窗口 |
| 稳定性 | 至少 2/3 开发窗口净收益为正；全部候选和对照执行完整 |
| 留出收益 | 扣成本后严格大于 0；相对动量规则的超额严格大于 0.1 个百分点 |
| 风险 | 留出最大回撤不超过 10%；UTC 日末权益计算的年化 Sharpe 至少 1.0，365 日年化 |
| 有效样本 | 留出至少 30 笔成交，其中至少 10 笔卖出；至少 20 个 UTC 日末持仓非零。成交不是独立往返交易，不能当作 30 个独立样本 |
| 成本 | 单边综合估计成本至少 15 bps，暂按费用与滑点合计估计；接入前按实际账户费率和成交情况校准，只能重做研究，不能替换旧结果 |
| 压力 | 成本至少翻倍；仓位上限 ±10%；目标延迟至少一根 K 线释放。四种场景都需有成交、持仓、正净收益，回撤不超过 10% |
| 统计 | DSR 至少 0.95、PBO 不超过 0.10；估计不可用即不能通过；统计仅覆盖登记过的候选 |
| 目标风险限额 | 单标的目标不超过 20%，总目标不超过 60%，现金缓冲至少 10%。两个标的的有效目标总上限为 40%；价格波动后的实际权重可能变化 |
| 证据 | 门槛在结果产生前冻结；数据与代码指纹一致；日志与决策、成交、权益、配置相符；全部日志独立对账无差异 |

延迟压力复用原始目标，在较晚时点按当时价格、账户和风控重新生成数量，随后仍按次根开盘撮合；初始等待期空仓。这是粗粒度目标延迟敏感性检查，不是实际秒级延迟、排队或订单簿仿真，不能声称已验证真实成交价格。

全程空仓即使零回撤，也会因成交、持仓、收益和统计不足而失败。规则基准胜出表示本轮 AI 尚无增益，不强行挑一个 AI 去模拟盘。

正式方案在开发段先筛选：候选必须完整、平均净收益为正，且至少 2/3 窗口为正。没有候选满足时立即归档，不打开最终留出、不花费剩余留出模型预算；该轮不能算回测准出。

## OKX 模拟盘进入小额实盘准备的门槛

要求同一策略、模型、提示词和风险版本，从真实 OKX 模拟账户回执取得证据；本地 paper 撮合和历史回测不能计入。

| 项目 | 要求 |
|---|---|
| 时间与样本 | 至少 60 个完整自然日、60 份日结对账；至少 30 笔交易所模拟成交、10 笔卖出、20 个持仓日 |
| 收益 | 扣实际模拟费及费用估计差额后的净收益为正，同时胜过现金和同区间规则影子基准；外部充值、重置、转账不能算收益 |
| 风险 | 最大回撤不超过 5%，单日亏损不超过 2%，UTC 日收益年化 Sharpe 至少 0.5 |
| 执行 | 完成决策比例至少 99%；95 分位不利滑点不超过 10 bps；无无法确认的订单、重复订单和风控越权 |
| 账目与恢复 | 订单、成交、余额、持仓每日核对，差异必须为零；断线重连、进程重启、撤单和紧急停机演练有证据 |
| 环境 | 模拟盘专用凭据和 `x-simulated-trading: 1` 同时核验；不得用实盘凭据代替 |

累计标准有待 OKX 模拟盘执行与证据采集接入后自动核验，目前只冻结要求，没有模拟盘已达标的记录。检查命令不会接受手填绩效来放行实盘，也不会启动任何账户。OKX 的模拟盘凭据和请求头要求见 [官方 API 文档](https://www.okx.com/docs-v5/zh/#overview-demo-trading-services)。

即使两个阶段都达标，也只进入小额实盘准备；实际资金规模、单笔和日累计限额必须由操作者明确设置。没有这些额度不激活实盘。不得自动转为满仓、杠杆或无限迭代。

## 使用方式与证据边界

```sh
.venv/bin/quantbot runtime crypto-policy
.venv/bin/quantbot runtime --root runs/crypto-research study-create --plan plan.json
.venv/bin/quantbot runtime --root runs/crypto-research study-run <研究ID> --allow-model-calls
.venv/bin/quantbot runtime --root runs/crypto-research study-admission <研究ID>
```

`plan.json` 使用现有研究格式，增加顶层 `"promotion_policy": "crypto_spot_v1"`，并在 `protocol` 中设置 `"execution_delay_bars": 1`。该策略把整套阈值放进冻结方案及方案指纹。`study-admission` 不修改旧结论、不调用模型或账户；回测门槛未全过时退出码为 2，返回逐项原因。没有预登记阈值的旧研究只能诊断，不能事后补成准出证据。

准出检查是研究层结果，不是券商执行许可。自动留出暴露检查仅覆盖当前研究目录，跨目录审计须另行保存。现有直接下单入口仍关闭；OKX 模拟盘的 AI 目标执行、持续回执采集和晋级连接仍需开发，不能把现有适配器的存在当作该流程已经接通。

首轮正式研究建议使用日线：3 × 41 根开发窗口、1 根隔离、61 根独立留出，共 185 根研究行情，另加预热。两组 AI 的开发最多 240 次决策，选中 AI 后留出最多 60 次，合计最多 300 次；规则和冻结目标压力测试不调用模型。日线与上一轮小时策略属于不同研究，结果不能直接拼接。真实调用须有本轮预算；先做开发段规则预筛，保留最终留出直到候选冻结并完成筛选。

公共历史行情不等于当时可得版本认证，本地留出隔离不能排除大模型训练知识污染。反复筛选的过拟合风险依据 [Bailey 等的原始研究](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf) 处理；该论文不为本项目的上述具体阈值背书。
