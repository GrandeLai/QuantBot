# AI 策略研究闭环

研究通过不等于交易准入。本流程只进行历史回测，不启用持续任务、券商或交易所账户。

## 使用入口

网页「运行中心 → AI 量化交易 → 回测研究与版本对比 → 策略研究闭环」：

1. 创建候选任务，指定相同市场、标的、历史数据、资金、成本与账户熔断阈值。可比较 1..6 个模型/策略/仓位配置。
2. 填写名称、假设、理由和放弃条件；在高级选项中确定窗口、预算及数值验收标准。
3. 点击「冻结研究方案」。这一步验证并保存实际输入数据，不调用模型。
4. 检查冻结方案；涉及 AI 时单独勾选模型调用授权，再执行研究。
5. 查看开发记录、最终留出权益、规则/现金/随机对照、压力测试、研究结论，并下载完整 JSON 证据。

候选默认暂停。研究使用独立初始现金账户，不修改候选的持续模拟账户或准入状态。

CLI 与网页共用实现，适合本地 Agent 编排：

```sh
# 默认 CLI 和网页都使用 runtime/automation。
.venv/bin/quantbot runtime create --name momentum-research --market crypto \
  --provider demo --source csv --data /absolute/path/crypto.csv --symbols BTC/USDT --bar 15m

# 将返回的任务 ID 填入下方 JSON，保存为 research-plan.json。
.venv/bin/quantbot runtime study-create --plan research-plan.json
.venv/bin/quantbot runtime study-run <研究ID>
.venv/bin/quantbot runtime study-show <研究ID>
.venv/bin/quantbot runtime studies

# AI 候选先配置模型，再明确授权执行：
.venv/bin/quantbot runtime study-run <研究ID> --allow-model-calls
```

研究卡片示例：

```json
{
  "job_ids": ["替换为候选任务ID"],
  "data_kind": "historical_unverified",
  "card": {
    "title": "动量持续性研究",
    "hypothesis": "趋势信号能在后续未参与选参的行情中提供正收益",
    "rationale": "检验行情趋势延续是否能覆盖交易成本",
    "failure_condition": "留出表现不能超过规则对照，或成本压力后失效则放弃"
  },
  "protocol": {
    "development_bars": 30,
    "folds": 3,
    "gap_bars": 1,
    "holdout_bars": 40,
    "min_observations": 30,
    "min_return": 0.0,
    "min_excess_return": 0.001,
    "max_drawdown": 0.10,
    "min_dsr": 0.95,
    "max_pbo": 0.5,
    "cost_multiplier": 2.0,
    "weight_perturbation": 0.10,
    "placebo_seeds": [7, 42, 99],
    "model_request_budget": 500
  }
}
```

默认数值是可修改的研究起点，并非经过市场验证的通用标准。文字放弃条件保留为研究说明；程序按冻结的数值标准判断，不会让模型解释文字并修改验收门槛。`data_kind` 是来源声明：合成行情必须指定 `synthetic`，网页也有对应选项；该类研究即使达到所有数值门槛，也只返回证据不足，不能判为研究达标。系统不会自动识别用户把合成 CSV 声明为历史行情的情况。

默认需要 `30 × 3 + 1 + 40 = 131` 根完成预热后的行情，额外预热长度依策略与市场决定。最多使用 500 根预热后的行情。`demo` 在此处仅指定确定性动量规则，研究必须提供 CSV 或明确的公开行情来源，不会自动生成合成行情。

CLI `study-run` 返回 0 表示全部试验完成；返回 2 表示运行、数据、授权等异常或试验未完整运行。研究是否达标必须读取 `report.conclusion` / `report.research_passed`，不能依赖退出码。

## 冻结内容与执行顺序

登记后冻结卡片、候选及完整配置、模型路由、系统提示词、源码指纹、行情内容、窗口边界、随机种子、淘汰标准和模型请求预算。复用 `ExperimentRegistry` 记录全部声明的候选试验；失败候选仍计入试验总数。

开发区间划分为互不重叠、等长的窗口，每个窗口从相同初始现金独立运行。全部候选接受开发窗口测试，先按完整性筛选，再按窗口平均收益、最差窗口回撤、候选 ID 确定唯一候选；选择及依据先写入数据库，随后才请求最终留出区间的决策。开发窗口参与选择，其最佳收益不是最终样本外证据。

最终留出只运行选定候选。基线为同一区间的价格行为规则（股票）或动量规则（加密），以及现金。规则基线固定采用本研究首个候选的配置，不随收益排名变更；它不是买入持有指数基准。

压力测试重放留出期间保存的**原始目标持仓**，不重新询问模型：

- 提高估计交易成本，等额调整限价容差以保留原始价格容差。
- 分别降低和提高单标的仓位上限（最高为 100%），重新经过风控与成交记账。
- 按预登记种子运行随机入场/空仓对照，使用相同标的、成本和风控。

这验证固定决策在不同执行约束下的敏感性，不等同于重新推理后的 AI 账户行为，也不覆盖任意策略参数扰动。随机对照的实际暴露和换手可能与候选不同，不能单独作为有效性证明。

每个窗口单独持久化，保留决策、订单、估计成本、权益曲线和错误。窗口之间不拼接复利曲线。运行中断或异常后不自动重试；再次执行中断研究只归档未完成状态，避免重复收费或重复使用留出区间。

## 两种结果

`execution_completed` 表示所有请求窗口、决策和对照完整，无模型错误或账户熔断中止。基础回测原有的 `passed` 继续表示运行检查通过，新增 `research_conclusion="not_assessed"`，与研究结论分开。

| `report.conclusion` | 含义 |
|---|---|
| `validated` | 满足本次冻结的全部研究标准；不代表可上线或稳定盈利 |
| `rejected` | 数据和运行足以判断，但收益、风险或稳健性未满足预登记标准 |
| `insufficient` | 运行不完整、样本不足、统计量不可计算，或最终留出已经被使用 |

达标要求开发和留出收益严格高于最低收益门槛，留出相对规则超额收益严格高于门槛，回撤不超限，三项压力测试仍满足收益/回撤标准，超过全部随机对照，以及 DSR/PBO 达标。

DSR 使用最终留出收益与本批所有候选在开发区间的年化 Sharpe 分布；PBO 使用本批所有候选对齐的开发窗口逐根收益。开发窗口之间不引入重置现金造成的收益跳变。CSCV 丢弃的头部余数在报告中注明。只有一个候选时 PBO 不适用；收益方差不足时 DSR 返回“证据不足”，不以零值替代失败。年化频率分别为股票 252、加密按 365 天与 K 线周期计算。

统计范围只包括本批预登记候选；外部试验及人工探索没有被自动计入。因此结论不能解释为普适的盈利概率。

## 数据与留出保护边界

- 复用 OHLCV、重复记录、交易日历、连续性、完整收盘、未来数据及指标预热检查；历史数据按区间覆盖验证，不要求覆盖今天。
- 缺少详情或不支持的公司行动落入输入首根至研究终点时，登记即拒绝，包含指标预热历史。带完整条款的整股拆并股和普通美元现金分红共用 [主回测公司行动会计](AI-CORPORATE-ACTIONS.md)，候选和规则对照遵守相同记账规则；持仓产生碎股等执行阶段限制会保留失败证据。
- 原始 CSV 更新不影响已冻结研究；冻结数据损坏、源码或候选配置改变时拒绝运行。
- 同一运行目录中，先前研究和基础/滚动回测已经使用的相同市场标的区间，被标记为已暴露。即使同时登记多个研究，执行前也重新检查。研究之间串行执行。
- 其他目录、外部回测、人工阅读和模型训练中的历史知识不能自动追踪；本地保护不能证明这些信息从未被看过。
- CSV/公开数据没有完整 PIT 证明。财报/新闻披露时点、复权修订与公司行动完整性仍需后续接入，报告明确保留 `point_in_time_verified=false`。

报告保存在 `<runtime根目录>/research/<研究ID>/report.json`，包含冻结行情实际内容、卡片、参数、提示词、指纹、阶段记录和全部试验。失败试验也可从 API 查看和导出。

## API 与本地 Agent

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/quantbot/runtime/research` | 提交研究 JSON，验证并冻结输入 |
| GET | `/api/quantbot/runtime/research` | 列出全部研究，保留失败或淘汰结果 |
| GET | `/api/quantbot/runtime/research/{id}` | 卡片、阶段、逐窗口记录与结论 |
| POST | `/api/quantbot/runtime/research/{id}/run` | 一次执行；请求体 `{"allow_model_calls": false}`，AI 需显式 true |
| GET | `/api/quantbot/runtime/research/{id}/export` | 含冻结行情的完整 JSON |

本地 Agent 可把用户想法整理成卡片、创建候选、调用登记/执行并解释报告。策略决策可使用配置中的兼容模型接口或本机 `codex_cli`，模型与推理强度随候选冻结；具体步骤和调用预算见 [本地 Codex 驱动](AI-CODEX-AGENT.md)。Claude CLI 尚未接入，研究执行器不自动生成或执行任意策略代码。
