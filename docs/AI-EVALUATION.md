# 滚动评估与版本比较

统一运行器支持美股日线和加密现货的历史时间隔离评估。它比较已经冻结的模型、策略和仓位参数，不训练模型，也不根据测试收益自动启用任务。

## 操作

先创建候选或复制旧版本，再执行：

```sh
# 一个候选也可以做多折评估。多个候选必须使用一致的行情和执行基础。
.venv/bin/quantbot runtime walk-forward <候选ID> <另一候选ID> --selection-bars 30 --test-bars 10 --folds 3 --gap-bars 1

# 参与版本中有 AI 时，需要单独明确授权该批次的模型调用。
.venv/bin/quantbot runtime walk-forward <AI候选ID> --selection-bars 30 --test-bars 10 --folds 3 --allow-model-calls

# 查看当前版本的完整报告；当前流程到复盘结束。
.venv/bin/quantbot runtime show <候选ID>
```

根目录参数写在子命令之前，例如 `quantbot runtime --root /完整路径 walk-forward ...`。网页「回测研究与版本对比」中选择候选，在「滚动样本外评估与版本对比」勾选版本并运行即可。工作进程无需启动。页面会显示各版本准入状态、逐折结果和当前版本失败原因。

HTTP：`POST /api/quantbot/runtime/evaluations/walk-forward`，请求字段 `job_ids`、`selection_bars`、`test_bars`、`folds`、`gap_bars`、`allow_model_calls` 与 CLI 对应。结果包含共同协议、版本比较摘要、每折选择和各版本评估记录 ID；完整账户、决策与订单记录在对应任务详情的 `evaluations` 中。

## 时间和账户规则

默认使用最近 **61 根预热后的 K 线**：30 根参考、1 根间隔、3 折各 10 根测试。还需此前足够行情计算指标：美股至少满足主策略预热要求，加密至少 35 根或 ATR 窗口要求。

| 阶段 | 行为 |
|---|---|
| 冻结 | 一次读取行情，保存不可变内容指纹、候选集合、源码/配置指纹与评估参数，再开始决策。 |
| 参考窗口 | 各候选在相同的较早区间独立回放；剔除决策不完整、模型错误或账户熔断的版本。 |
| 选择 | 按参考期净收益降序，其次按回撤较小、任务 ID 字典序打破平局；先保存选择，再进入测试。没有合格版本时明确记录空缺。 |
| 测试窗口 | 所有候选和同一个规则基线在后续等长区间回放，测试结果不参与本折选择。窗口之间不重叠，下一折参考窗口可包含届时已经过去的测试历史。 |
| 决策输入 | 每次只传递该收盘时点及此前的特征和账户。特征可利用窗口之前及隔离间隔内已知的历史；间隔用于隔开选择结果与测试，不会抹去已经公开的行情。 |
| 账户和撮合 | 每个参考/测试窗口从相同现金重新开始，最后一个收盘只估值而不产生新决策。订单在次根开盘含估计成本成交，末尾持仓按市值计价，不虚构末日清仓。 |
| 汇总 | 测试窗口收益取算术平均，另列最差窗口收益、最差窗口回撤、成交和错误；不拼接资金、不计算跨窗口复利、年化收益或组合回撤。 |

模型连接在各窗口重新创建。报告的 `selected_strategy` 仅汇总每折依据参考窗口选中的版本；`unselected_folds` 明确列出空缺折数，全部空缺时收益是 `null`，不补成零收益。不将未入选的现金基线作为隐式替代策略。

模型、主策略参数和仓位风控允许因版本而异。比较时必须一致的字段包括市场、标的及顺序、周期、数据来源和路径、起始日期、发布延迟、初始资金、估计成本、订单价格缓冲，以及账户日损/回撤暂停阈值。各版本独立计算自身参数的特征；规则基线固定使用本批次第一个版本的参数，因此报告保留其配置指纹。

## 准入与用量

- 一批 1..6 个候选；参考窗口 3..200 根，测试窗口 3..100 根，2..10 折，隔离间隔 0..100 根。总时间范围最多 500 根预热后行情。数据不足直接失败，不自动减少窗口或折数。
- 每个候选必须在所有参考和测试窗口中完成每个可决策时点，模型错误为零且无账户熔断。失败会撤销该候选先前的评估准入，其他通过候选仍保留评估结果。收益和排名不作为软件准入条件，空仓策略不会因没有成交而被拒绝。
- 运行中的 `paper` 版本需先复制为新候选。比较使用每个任务的评估互斥锁；提交时再次检查源码和参与任务状态，整批准入结果原子保存。评估不会修改模拟账户，不自动启用任何版本。
- 启用/恢复须有与当前版本一致的最新通过报告，且行情证据仍存在、内容指纹一致。基础回放与滚动评估都保留具体类型；基础回放通过只代表最小本地模拟准入。
- 模型调用次数上界为每个 AI 版本 `折数 × (参考根数 + 测试根数 - 2) × (1 + 备用模型数)`，再对所有 AI 版本求和。模型网关每条路由至多尝试一次；费用由实际供应方计费。参考窗口重复使用历史也会再次调用模型。
- `provider_calls` 是决策入口次数，不是包含所有备用尝试的 HTTP 请求总数。`usage` 汇总当前版本参考和测试调用，`candidate` 汇总测试窗口。未报告 token 用量显示「未提供」并计数；有报告的部分才进入累计值。失败请求或失败的备用尝试可能已计费，用量报告不等于账单。

## 证据边界

这里的「样本外」指代码按历史时间划分参考和测试窗口。模型可能预先学过该时段的信息，人也可能看过行情再指定候选与参数；本功能不能排除这些影响，不宣称严格未见数据或统计显著性。重复调参后再运行同一段历史，依旧属于研究。

验证真实模型效果需要固定协议后的前瞻观测。当前仅支持本地次根开盘模拟，尚未包含真实流动性、部分成交、完整公司行动记账、真实费用及资金流水。富途、老虎和 OKX 交易渠道接入继续暂缓。

本轮实际检查与证据边界见 [AI-EVALUATION-VALIDATION.md](AI-EVALUATION-VALIDATION.md)。
