# QuantBot 合并验收记录

完成日期：2026-10-06。版本：0.2.0。目标目录：`/Users/bytedance/code/QuantBot`。

## 结论

PABot 和 StockBot 的业务代码已合并到一个 `quantbot` 安装包；新的主要功能是通过可配置的大模型进行日线量化决策，经过确定性风控后进行回放或模拟盘执行。新链路实际复用了两套原有代码，不依赖原目录或原虚拟环境才能导入业务模块。

迁入 203 个原业务包模块，加上原 PABot 命令入口；完成合并后共有 216 个业务 Python 模块。原入口保留为研究工具，新交易链路在 `quantbot.ai` 中统一实现。

价格行为属于 AI 量化交易的输入/子策略。模型可以使用它，也可以基于其他已接入的因子提出仓位；当前版本主链路接入的是日线价格、成交量、价格行为及因子评分，尚未接入新闻和财报。模型提议不能绕过独立风控。

完整回归保留了旧代码在当前 NumPy/Pandas 组合下的弃用提示；没有把提示隐藏成“无告警”。当前测试通过，未来依赖升级仍应回归。固定验收依赖有助于复现。

关键新覆盖包括：

- 未来行情行不会影响早于它的信号、特征或快照身份；信号日缺失日线时拒绝继续。
- 模型的未知/重复代码、过期快照、未来时间、NaN、字符串权重、额外工具字段、拒答及截断回答不能生成订单。
- AI 能在没有价格行为入场信号时提出多头仓位，但不能突破现金、单仓、总暴露和止损风险预算。
- 低置信度保留既有仓位；账户交易限制阻止订单；既有止损取券商实际值，不能靠虚构更紧的止损扩大风险预算。
- 高置信度的保持持仓提议不产生多余减仓；现有持仓按市场参考价估值，仅新增买入股数使用缓冲限价预留预算。
- 次日开盘成交，超出预算限价的跳空取消；模型异常时停止新决策，仍保留保护性风险处理。
- 模拟盘买入附带 OTO 止损；同执行日重启不重复决策或下单；主单或替换止损响应丢失时先查原订单 ID，未知 404 不作为盲目重提的依据。
- 部分卖出后恢复残余持仓止损；外部工作订单和未受保护持仓触发门禁；模型推理途中账户变化时停止提交。
- 已存在的决策输出在调用模型之前拒绝，避免重复消费模型额度。

## 合并中修复的问题

1. **StockBot 配置审计把缓存当成调用方。** 改为只扫描对应研究源码中的 `.py`，并明确说明 `daytrade.live_submission_enabled` 是配置校验关闭实盘的约束，`portfolio.normal_fraction` 是组合部署的预留字段，独立实验仍使用显式资金参数。没有假装预留资金字段已生效。
2. **跨 Python 版本的碎股累计与剩余数量归一不一致。** 每个订单使用自己的成交片段进行 `math.fsum` 汇总，对账最终片段也使用相同口径。保留严格超额成交检查，避免扫描所有历史成交造成性能退化；Python 3.11 和 3.14 均通过相关测试。
3. **迁移后的研究配置、源码身份和文档路径。** 更新内部导入及根路径，并同步相关测试；旧实盘入口不通过 QuantBot 主交易入口暴露。
4. **旧价格行为实盘入口能够绕过独立的发布门禁。** 合并后的兼容交易函数明确拒绝 `live`，即使配置和确认参数都满足，也不能在新策略尚未验收时创建实盘券商客户端。原 PABot 文件不改动。
5. **新目标仓位换算将买入限价缓冲作用于既有持仓。** 保持当前持仓时会误减仓，减仓数量也会偏大。现有持仓使用市场参考价，买入限价只预算新增股数，并处理保持持仓时的浮点舍入；AI 和纯价格行为对照均补充回归。

## 尚未验证及当前限制

- 真实云端或本机大模型推理尚未验证。本次没有读取原 `.env`，没有配置真实模型密钥，没有消耗真实模型额度。
- Alpaca 适配使用本机模拟券商测试响应，尚未连接真实模拟账户；没有发出真实券商订单，更没有实盘交易。
- 当前新交易主链路是美股日线、整数股、多头，支持 Alpaca 模拟盘。StockBot 的 Moomoo/分钟级等能力保留在研究工具中，尚未接入新 AI 主链路。
- 主链路是静态保护性止损。模拟盘 OTO 使用 GTC 保留隔夜止损，回放入场按 DAY 处理；实际成交、限价路径和滑点不承诺完全一致。
- `price_action` 规则对照复用新风控/执行口径，不能拿它与原 PABot 的完整回测历史收益直接比较。
- 历史模型推理可能受预训练记忆影响，自选股票池还可能存在幸存者偏差。策略优劣需要点时数据、成本评估及新的前瞻模拟证据。
- 没有创建或推送 GitHub 仓库，没有删除或改写旧项目，没有进行 Docker 实际构建或部署。
