# 回测异常留痕与中断检查

主回测、滚动评估和预登记研究现在逐步持久化证据。每次决策调用前，先把实际行情/公告上下文和账户输入写入只追加 JSONL，并刷新到磁盘；调用返回后保存通过风控的决策，每根行情保存账户状态与模拟成交。写入失败会阻止后续调用。

账户历史中的持仓、止损和待执行订单使用独立快照。修复前的报告可能因后续交易改变同一对象，显示错误的历史持仓；已有报告保留原样，应重新运行以获得修复后的历史明细。此问题本身不改变已记录的权益、现金和收益标量。

## 回测状态

新评估开始时撤回候选先前的通过状态。只有本次完整评估成功保存后，才能重新成为 `evaluated`。中途异常、进程强制退出或比较批次部分失败，都不能继续沿用上一轮的通过结果。

- `completed`：回放循环已结束；还须检查 `execution_completed`。模型错误或风控暂停可能使该值为 `false`。
- `failed`：捕获到了异常，保留已写入的调用前输入、决策和成交，异常继续向调用方传播。
- `unfinished`：没有可信的终态，可能仍在运行，也可能已中断。未确认调用的响应与计费未知，不能自动重试。

日志保留逐决策尝试，不把它当作模型供应方 HTTP 请求数；备用模型、网关内部请求与真实费用仍需供应方记录核对。日志是本地工程证据，不是第三方签名认证。

失败研究的运行看板也会汇总已落盘的决策尝试与已报告 tokens，并分别显示缺失用量、结果未确认和次数未知的试验。被风控拒绝但已收到的有效响应保留在失败记录中；缺失部分不会按零用量处理。

## 取回证据

```bash
quantbot runtime replay-show /absolute/path/to/candidate.jsonl
```

该命令只读检查，不创建运行账户或尝试恢复交易。返回终态、尝试/已确认调用数、未确认的时点、最后持久化账户和逐条记录。完整执行成功返回 0，其余返回 2。末尾若因强制退出留下半行，会标记 `incomplete_tail` 并保留此前完整记录；中间记录损坏则明确报错。

添加 `--reconcile` 可独立重算现金、持仓和损益；使用契约与限制见 [回测账目核验](AI-RECONCILIATION.md)。

普通评估在报告中提供 `journal_directory`，目录内 `manifest.json` 保存冻结输入身份与比较候选，各回放写入独立 `.jsonl`。一键回测发生异常时生成 `failure.json`，含原始输入、配置、已有事件与部分回放；网页显示“下载失败报告”，不把失败展示为完成。

创建证据目录之后发生的输入校验失败仍使用 HTTP 400，并附失败报告下载地址；执行异常使用 HTTP 500。尚未创建回测目录的请求格式错误直接返回校验原因，不生成空报告。

研究的每个试验有独立日志。检测到遗留 `running` 研究时，恢复操作只归档中断和已有证据、将未完成试验标记失败，不再次调用模型。失败试验的日志直接包含在导出的研究结果中。

中断的基础/滚动评估也被计入最终留出集的已暴露检查：一旦评估启动，其声明区间会保守地按已使用处理，避免异常记录丢失后再次把相同区间称为“未见数据”。

## 离线验证

```bash
.venv/bin/python docs/examples/validate_replay_recovery.py \
  --output runs/replay-recovery-validation-new
```

样例使用合成加密行情与本地规则，依次验证正常完成、第二次决策抛出异常、第二次决策直接退出进程。每种情景使用独立日志，保留上一次通过记录但撤回当前准入；网络、真实模型和券商调用应为 0。输出目录不可复用。

此机制不承诺断电后可以自动继续。磁盘不可写时可能无法记录最后一个错误，但此前已完成的记录不会被主动覆盖；需要人工修复存储并检查未确认调用。

本机验收及对应产物见 [故障恢复验证记录](AI-REPLAY-RECOVERY-VALIDATION.md)。
