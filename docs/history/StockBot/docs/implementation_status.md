# Trustworthy return implementation status

Status date: 2026-08-07.

## Completed in code

- Moomoo OpenD support is isolated behind a simulation-only US-equity adapter
  using the official `moomoo-api` package.
  It discovers or selects an active simulated account, refreshes funds,
  positions and today's orders, and supports explicit DAY limit-order
  place/query/single-order-cancel operations. Order-ID and submission-marker
  reconciliation use a bounded 90-calendar-day history fallback when no
  matching today order exists. Every account-scoped SDK call that accepts an
  environment supplies `TrdEnv.SIMULATE`; the environmentless account-list
  call is used only to select a validated simulated account. Real mode and
  API-based trade unlock are absent. The adapter disables the official SDK's
  console handler before opening a context, preserving the CLI's one-JSON-line
  stdout contract while retaining SDK file logs. Network uncertainty after
  place/cancel is never retried and is surfaced as requiring broker
  reconciliation. These operational checks do not create formal Paper
  promotion evidence. Local code and fake-SDK tests are not live-return or
  trustworthy-profit evidence.
- `ExperimentRunReport` provides one immutable, canonical envelope for
  comparable experiment runs. It hashes experiment/run identity, run type,
  observation time, logical dataset, actual input materialization,
  configuration, source code, execution/cost model, the named baseline/stress
  cost suite, outputs, metrics and admission fields.
  Evidence and completion-audit loading preserve the corresponding
  `input_materialization_hash`, `output_hash`, `report_hash` and
  `cost_suite_hash`.
- `ExperimentExecutionLedger` is the canonical one-shot state machine beside
  the exposure ledger. Only its `complete` transition may create the persisted
  result/receipt pair; a hand-written result cannot promote a merely started
  run, exact retries are idempotent, and formal materialization rejects an
  alternate ledger path.
- Formal admission is rebuilt from canonical raw execution artifacts instead
  of trusting report summaries. The verifier binds permit, execution receipt,
  result and artifact hashes; recomputes report metrics, admission flags and
  reasons; and only then creates a verifier-owned authenticated evidence row.
  Normal proves per-security PnL/equity conservation and independently derives
  5/10 bps fees and turnover from pre-trade equity/traded notional. DayTrade
  proves fill/daily-ledger conservation and derives long/short fill prices from
  pre-cost event prices at 5/12 bps. Direct strategy-evidence signing is no
  longer a public API.
- Evidence keeps two data identities intentionally: `dataset_hash` is the
  logical bundle/permit identity and `input_materialization_hash` is the
  content actually read. Both must be valid; a composite permit identity is
  not required to equal a materialized bar/read digest.
- `experiment-acceptance-report` verifies a canonical report and can compare it
  with a baseline report without reading market data or consuming an exposure
  permit. It fails on an invalid report, failed admission or mismatched logical
  dataset, materialized input, code, cost model or cost suite. This is an
  integrity/comparability check, not independent proof of profitability or
  sealed-data custody.
- Experiment dispositions are fixed: Normal H1 and DayTrade H9 are
  preregistered, H3 is the frozen survived baseline, and H4-H8 are retired.
- Retired experiments remain in global DSR/PBO multiplicity but can run only as
  non-selectable historical audit replay and cannot consume exclusive data.
- Exposure ledger schema v2 signs a complete `read_interval` (including
  warmup) separately from the `protected_holdout_interval` used for
  exclusivity and anti-replay. Existing v1 chains remain verifiable and retain
  their older, more conservative full-read protection. Exact granted
  run/manifest retries and exact denied retries are idempotent for crash
  recovery; run-ID identity drift is a chained denial. Exposed 2025-2026 v1
  sealed records remain read-only and cannot become current permits.
- Exposure timestamps are generated by the ledger's internal UTC clock;
  future caller timestamps and premature sealed permit replay fail closed.
- Every legacy/static loader rejects unreleased sealed-window overlap before
  calling a cache or market-data source.
- DayTrade sealed access is reserved for the single frozen H3-vs-H9 run.
- The standard Normal CLI can resolve a deployment adapter using
  `--adapter module:callable` or `STOCKBOT_NORMAL_ADAPTER` and requires the
  canonical exposure ledger.
- `normal-experiment-run --experiment-id` dispatches the frozen
  `normal-h1-quality-diversification` path or the separately preregistered
  `normal-h2-capital-efficiency` audit path. H2 is `completed_rejected`, requires
  `--historical-audit-replay`, and cannot consume fixed/sealed data. Both share
  the same verified PIT input, sessions, baseline provider and cost protocol;
  this is execution plumbing, not a new H1 or H2 return result.
- `strategy-readiness` accepts the intended warmup interval and verifies, using
  metadata only, that bundle and partition coverage contains the complete
  actual read interval. It also verifies any existing ledger chain and checks
  that the canonical ledger parent is writable, without claiming or reading
  protected market-data contents. Its payload exposes both the requested and
  warmup-expanded read intervals; metadata coverage is calendar-date coverage,
  while exact trading-session coverage remains deferred until after a permit.
  Normal and DayTrade must use their frozen full research/adaptive/sealed
  request windows. Normal freezes the three mode-specific factor warmups;
  DayTrade freezes the execution path's 60-calendar-day warmup, and H3 is
  research-only. Adapter specs are inspected statically without importing
  deployment code. Sealed H1 readiness verifies the signed adaptive-validation
  artifact and trusted Normal trial issuer keys, while final identity
  compatibility remains a pre-claim gate. Sealed H9 readiness similarly
  verifies the independent signed 2023-2024 adaptive-validation artifact and
  forbids embedding the earlier H1-H8 historical artifact in the sealed
  universe manifest.
- The normal allocator's capital leak is measured, repaired and declared.
  Constrained capital can be redistributed, volatility targeting can be
  two-sided, and the whole selection can be funded; all three default to the
  historical shrink-only behaviour and are rejected by the frozen H1 runner.
  `NormalAllocationReport` now reports `capital_utilization` and
  `risk_utilization`.
- `normal-h2-capital-efficiency` was preregistered (2026-07-26) as a
  single-variable experiment over H1's baseline sleeve and is now
  `completed_rejected` after the research and adaptive runs failed its return
  gates. The normal family still declares two trials, both counted in global
  DSR/PBO multiplicity, and
  `run_normal_h1_experiment` checks its own declaration rather than the family
  total. `config/stockbot.example.toml` now keeps the frozen H1-safe allocator
  defaults; the H2 profile exists only in the historical audit path. See
  `docs/normal_capital_efficiency.md`.
- `stockbot.normal.research_adapter` builds development-free point-in-time
  artifacts from plain daily bars, rebuilding one truncated adjustment vintage
  per rebalance so a present-day download cannot be used retroactively. It
  cannot produce admissible data: the tier stays `DEVELOPMENT_FREE`, the master
  is never `admission_verified`, and `require_final_admission` refuses it.
- A free-data H2 research replay over 64 US large caps confirms the capital
  repair (utilization 0.43 to 0.87 in 2010-2020, 0.45 to 0.88 in 2021-2024) and
  rejects H2 as alpha in both windows. It also shows that the tested 15%
  volatility-target configurations did not satisfy the original 15% formal
  drawdown ceiling. Evidence:
  `artifacts/normal/h2_capital_efficiency_free_research.json`.
- The CSCV/PBO gate used to switch itself off whenever the observation count had
  no even divisor, which is roughly half of all runs. `cscv_partition` now trims
  the remainder and reports `dropped_observations`; both normal runners and the
  DayTrade validation path use it. With the gate live, the H2 2010-2020 research
  window reports PBO 0.715 against a 0.05 threshold.
- `risk.max_normal_drawdown` was hashed but enforced nowhere.
  `NormalDrawdownPolicy` makes it enforceable and the backtester applies it on
  the daily risk clock; a monthly-only check left the drawdown unchanged.
  Measurement shows no tested configuration reaches the 0.15 limit (legacy
  0.190, capital-efficient 0.332, with daily control 0.243). Defaults to
  disabled.
- The drawdown acceptance ceiling and the operational trigger are separate
  controls even though both currently preserve the original 0.15 value.
  `validation.normal_max_drawdown` drives backtest/formal admission and
  `risk.max_normal_drawdown` drives the running-book review/halt policy. The
  admission ceiling is no longer inferred from the volatility target. The
  separation does not rescue H2: its 0.332 research and 0.197 adaptive
  drawdowns both exceed the formal 0.15 ceiling.
- `strategy_admission` carried its own hardcoded ceilings. They are now the
  named constants `NORMAL_ACCEPTANCE_MAX_DRAWDOWN` (0.15, imported by the
  experiment runner so the two cannot drift), `DAYTRADE_ACCEPTANCE_MAX_DRAWDOWN`
  (0.05, unchanged) and `DAYTRADE_ACCEPTANCE_STRESSED_MAX_DRAWDOWN` (0.07,
  unchanged). The Normal boundary is pinned by tests on both sides and runtime
  configuration may tighten, but cannot loosen, the 0.15 policy.
- The `[validation]` section had no consumers at all: every acceptance
  threshold was a literal written twice, once in `normal/experiment_runner.py`
  and once in `strategy_admission.py`. They are now the frozen types
  `NormalAcceptanceThresholds` and `DayTradeAcceptanceThresholds`, consumed by
  both the experiment runners and the formal admission gates, and reachable
  from `RuntimeConfig.normal_acceptance_thresholds()`,
  `daytrade_acceptance_thresholds()` and `paper_promotion_min_sessions()` —
  all six declared keys now drive a gate. The "cannot weaken admission policy"
  rule is enforced on the type, so no construction path can loosen a
  threshold. Pure refactor: the free-data H2 numbers are unchanged.
- The remaining unread keys are consumed. `execution.slippage_bps_per_side`
  now enters the per-side cost rate for both families (default 0.0; 10 bps
  costs 0.33 points of annual return on the normal book at 1.55 turnover) and
  the frozen H1 cost-model hash records the zero explicitly.
  `portfolio.normal_fraction` is exposed through `RuntimeConfig.normal_capital()`;
  at a 100,000 account the liquidity cap does not bind, so the split changes
  attribution and dollar amounts but not the sleeve's own return.
  `normal.residual_skip_months` reaches the provider and is frozen at 1 by both
  runners. `normal.execution_price` no longer offers the unimplemented "vwap".
  The root cause of the whole class was that `load_runtime_config` had no
  caller: the CLI never read a config file. `resolve_runtime_config` now loads
  it from `--config` or `STOCKBOT_CONFIG`. The data feeds join the Alpaca
  resolution chain behind flag and environment; the broker names are
  restricted to implemented adapters and resolved by `broker_adapter_type`
  with a same-broker failover rejected; `normal.universe_mode` refuses to serve
  the legacy mega-cap list to a `point_in_time` declaration;
  `normal.execution_price` is checked against what the backtester implements;
  and `validation.min_paper_sessions` reaches the gate through
  `paper_promotion_gate_from_runtime`. `DeclaredKeysHaveConsumersTest` keeps
  the audit running as a test so a new key cannot quietly become inert.
- `risk.max_daytrade_drawdown` had the same enforced-nowhere defect as its
  normal counterpart. `daytrade.enforce_drawdown_halt` (default false) now
  stops new entries once the sleeve is down by that fraction from its peak,
  deciding the halt from equity observable before the session opens.

## Current real-data readiness

The checked environment is not ready to run a trustworthy return experiment.
It has no configured external PIT root, canonical ledger/HMAC key, production
Normal adapter, adapter attestation, trusted calendar/universe/experiment
issuer keys, signed Normal adaptive-validation artifact, signed dynamic Top-50
manifest, complete frozen minute cache, signed DayTrade adaptive-validation
artifact, or the H1-H8 historical trial artifact needed to reconstruct that
adaptive result. The project-local Moomoo profile supplies Pandas and NumPy for
the broker SDK, but PyArrow and DuckDB remain absent and this does not provide
point-in-time research data.

Consequently:

- Normal H1 has not produced a new baseline/candidate return.
- The H1/H2 CLI dispatcher has not changed the existing development rejection
  of H2 as alpha and has not produced formal H2 admission.
- Dynamic Top-50 H3 has not been reconstructed on real PIT data.
- H9 has not produced a candidate return or formal admission result.
- No new trustworthy Normal or DayTrade return improvement is established by
  the reporting/evidence work.
- Real DayTrade order submission remains disabled; the retained live-cycle
  command is a fail-closed historical-replay surface.
- The repository now targets Moomoo OpenD and `moomoo-api` 10.9.6908 or newer
  within major version 10; Futu OpenD is not reused. On 2026-08-07, an active
  Moomoo US simulated account completed the real OpenD path: `snapshot`, one
  share AAPL RTH DAY limit `place`, exact-ID `query` to `SUBMITTED`, `cancel`,
  terminal `query` to `CANCELLED_ALL`, final `snapshot`, and exact submission-
  marker reconciliation. The order dealt quantity was zero, final positions
  were empty, and frozen cash was zero. This proves the simulated operational
  path only; it is not live-return or `PaperPromotionGate` evidence.
- A separate `moomoo-paper-canary` engineering path now provides durable
  single-instance simulated-account execution over the independent ten-symbol
  canary universe. It is forced to `SIMULATE` through loopback Moomoo OpenD,
  requires an explicit simulated-action confirmation, rejects stale or
  incomplete quotes, reconciles every write, persists restart state, and must
  prove all canary positions flat before it can complete successfully. The
  default liquidation lead is ten minutes before the regular US close. There
  is no independent share-count or position-count cap, but buying power,
  whole-lot sizing, the long-only boundary, the configured universe, and the
  end-of-day liquidation gate remain mandatory. Configurations whose symbol
  count cannot fit the worst-case cancellation plus one exit attempt per symbol
  inside the liquidation lead are rejected before trading. `--preflight-only` exercises
  the read/state/lock checks without submitting or cancelling an order.
  Completed sessions are archived immutably before the next trading day's
  durable state is created; unfinished sessions never roll into another entry
  run and can advance only through containment. Recovery uses one fresh today
  order snapshot plus one bounded history snapshot instead of per-order query
  fan-out. Broker reads cannot poll faster than five seconds; fresh funds,
  positions, today-order, and history-order calls also use endpoint/account
  process-wide limiters. Place and cancel calls enforce both sliding-window and
  minimum-spacing limits, while durable timestamps preserve canary write
  capacity across restarts and reserve entry capacity for exits. Quotes are
  refreshed after limiter waits, and refreshed ENTRY quantities cannot exceed
  their original notional budgets. Each write rechecks the session gate after
  WAL/event handling and again inside the adapter after shared-quota waits,
  immediately before the SDK call; a provably unsent write that crosses the
  gate becomes durable `ABORTED` state. Event-output failures cannot interrupt
  containment. Lost entry, exit, and cancel acknowledgements converge through
  read-only reconciliation in the same process until recovery or regular close;
  none of those uncertain writes is repeated. Restarted `ENTERING`,
  `LIQUIDATING`, or ENTRY `SEND_STARTED` state goes directly to containment.
  Transient liquidation reads can never produce a false `FLAT`; monitor recovery
  continues into liquidation in the same run. Stale exit quotes are refreshed, while
  non-atomic position/order snapshots are reread until their canary-owned
  quantities converge. Cumulative dealt quantity and terminal order evidence
  are monotonic across rereads; missing or regressed order/position rows cannot
  prove `FLAT`. A prior-day HALT interrupted while waiting for the next open
  remains recoverable. States outside the bounded 90-calendar-day broker
  history window require manual recovery.
  Canary outputs are operational diagnostics only and cannot be promoted into
  H1/H9 return claims or `PaperPromotionGate` evidence.
- On 2026-08-07, the real-time engineering canary submitted six simulated US
  entry orders. The sixth acknowledgement was lost during an OpenD timeout;
  the persisted marker was not resubmitted and later reconciled to the actual
  broker order. The session stopped the remaining four entries, entered
  containment, bulk-reconciled all orders, and submitted six matched exit
  orders. All six entries and all six exits reached `FILLED_ALL`. At
  11:49:39 ET the durable state reached `FLAT`; an independent fresh snapshot
  then showed zero positive-quantity positions, zero working orders, and zero
  frozen cash. Moomoo retained one zero-quantity position row, which is not
  counted as exposure. This is broker-plumbing and recovery evidence only,
  not strategy-return or `PaperPromotionGate` evidence.
- The 2026-08-01..2028-07-31 sealed interval remains unreleased and must not be
  read before 2028-08-01 UTC.

## External requirements

Before research/adaptive execution, supply the resources reported by
`strategy-readiness` and verify the external adapter/data producer. Before a
future sealed run, an independent storage/KMS owner must prove that the sealed
payload and release authority were inaccessible to the research process. The
repository's application guard alone cannot establish that custody fact.
