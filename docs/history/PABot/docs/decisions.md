# 中期决策项评估（P4）

> 本文档评估三个需要用户拍板的中期方向。每项给出现状、方案、成本与建议，
> 决策后对应章节的建议将转为执行计划。

---

## 决策一：付费无幸存者偏差数据源

### 问题

当前 yfinance 免费数据有三个结构性缺陷，已用工程手段缓解但无法根治：

| 缺陷 | 现有缓解 | 残余问题 |
|------|---------|---------|
| 退市股无历史数据 | 点时成分股名单 + 改名别名映射（恢复约 3.9 万候选日） | 795 只历史成分股中约 140 只（扣除别名恢复后）仍缺失，多为破产/被收购的"困境股"，回测结果系统性偏乐观 |
| 前复权价格随刷新漂移 | 数据快照版本化（实验可复现） | 快照只是"冻结了某一次的漂移"，不是数据真值 |
| 代码复用污染 | 别名映射 + 点时窗口天然隔离 | 依赖人工维护映射表 |

### 方案对比

（联网调研纪要见本目录 `data_vendor_research.md`，含价格与出处）

- **Norgate Platinum（$630/年）**：退市股全覆盖（约 2.5 万只、1990 起）、
  复权口径固定、含 S&P 500/400 逐日成分标记——三个痛点全解。
  **关键限制：数据更新器仅支持 Windows**，Mac 环境需常驻虚拟机。
- **EODHD（$19.99/月 ≈ $199/年）**：REST API，Mac 无缝；30+ 年日线含退市股
  （2018 年前退市的仅价格数据，日线回测够用）；S&P 500 历史成分免费自带。
  S&P 400 成分需另加 $29.99/月 且仅 12 年历史。
- **维持 yfinance**：零成本，靠快照 + 别名 + 诚实披露残余偏差过日子。

### 建议

模拟盘阶段维持 yfinance（当前的偏差已量化并披露，不影响 paper 验证）；
**决定投入实盘资金前升级 EODHD（$19.99/月）**——Mac 友好、成本最低、
退市股与固定复权口径直接根治两大痛点；若未来确需 S&P 400 全历史成分
再评估 Norgate + 虚拟机的组合。切换成本主要是数据适配层 + 全部历史基线
重新标定（约一天工作量，所有消融结论需在新数据上重跑确认）。

## 决策二：S&P 400 中盘股池扩展

### 动机

绩效归因显示利润引擎是"少数大赢家 + 金字塔加仓"（top-10 交易占利润
100%+）。中盘池提供更多处于生命周期早期的潜在大赢家。

### 风险

1. 免费的 S&P 400 点时成分数据可能不存在或质量不可用（调研纪要见附录）；
2. 中盘退市率高于大盘，yfinance 缺失率会显著高于大盘的 22%，
   测出的数字自带更大的向上偏差；
3. 中盘流动性差，5bp 滑点假设偏乐观，消融必须同时跑 10-15bp。

### 建议

**排在决策一之后**。调研确认免费的 S&P 400 点时成分数据不存在
（Wikipedia 变更表仅回溯 2012 且不完整）：
- 走 EODHD 路线：需另加 $29.99/月 附加包且仅 12 年历史——性价比存疑；
- 走 Norgate Platinum：1991 年起全历史成分，数据障碍彻底消失，
  但引入 Windows 虚拟机依赖。
若不升级数据源，中盘扩展测出的数字可信度不足，**不建议投入**。

## 决策三：部署方式（从笔记本 cron 到云主机）

### 现状与风险

系统当前设计为本机 cron 每日触发。笔记本环境的固有风险：
休眠/关机错过运行窗口、网络切换、系统更新打断。
已有缓解：幂等性（漏跑后次日自动补齐状态）、死人开关
（`PABOT_HEARTBEAT_URL` 心跳，外部服务侦测停摆）。

### 方案

| 方案 | 成本 | 可靠性 | 备注 |
|------|------|--------|------|
| 笔记本 cron + 心跳告警 | $0 | 中 | 现状；漏跑有告警但无自动恢复 |
| 云主机（任一 $5/月 VPS） | ~$5/月 | 高 | 推荐；部署 = git clone + venv + crontab 三步 |
| GitHub Actions 定时任务 | $0 | 中高 | 免费但有排队延迟（可达数十分钟），密钥存 Actions Secrets |

### 建议

模拟盘先用**笔记本 cron + 心跳**跑通流程（零成本验证）；
转实盘时同步迁移到 **$5/月 VPS**（美东机房更佳，时区问题消失）。
部署清单：

```bash
# VPS 上（Ubuntu 为例）
git clone <repo> && cd PABot
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
# 写入密钥与通知配置
echo 'export ALPACA_API_KEY=...; export ALPACA_SECRET_KEY=...' >> ~/.profile
echo 'export PABOT_WEBHOOK_URL=...; export PABOT_HEARTBEAT_URL=...' >> ~/.profile
# 美东时间 09:35 触发（服务器设 UTC 时为 13:35 或 14:35，随夏令时调整；
# 简单起见直接把服务器时区设为 America/New_York）
crontab -e
# 35 9 * * 1-5 cd ~/PABot && .venv/bin/python main.py paper >> logs/live.log 2>&1
# 50 16 * * 5  cd ~/PABot && .venv/bin/python main.py reconcile >> logs/reconcile.log 2>&1
```

## 汇总建议的执行顺序

1. **现在**：笔记本 cron 跑模拟盘（零成本，全部安全机制已就位）
2. **模拟盘 1 个月后**：复盘影子对账与实际滑点数据
3. **决定投入实盘时**：同时执行 决策一（Norgate）+ 决策三（VPS）
4. **数据源升级后**：执行 决策二（中盘扩展消融）
