# PABot —— 基于价格行为的美股趋势交易系统

PABot（Price Action Bot）是一个**只交易美股**的量化交易系统，信号完全来自
**价格行为（Price Action）**：市场结构（摆动高低点）、突破、回调反转 K 线形态，
不依赖 MACD / RSI 等震荡指标。系统同时支持：

- ✅ **历史回测**（2015 – 2025，组合级、事件驱动、严格无未来函数）
- ✅ **模拟盘**（Alpaca Paper Trading，免费）
- ✅ **实盘**（Alpaca Live Trading，与模拟盘同一套代码，一个开关切换）
- ✅ **证据化复盘**（只追加账本、候选拒绝原因、订单/成交/持仓完整链路）
- ✅ **故障后冻结**（启动前只读核对未决订单，未知或未交接状态一律 HOLD）
- ✅ **受控调整**（单变量预注册实验、Paper campaign、不可覆盖候选包、发布门禁）

回测、模拟盘、实盘**共用同一份策略代码**（`pabot/strategy/`），
保证你回测出来的系统就是你实际交易的系统。

> 当前定位：核心算法与故障冻结边界已具备完整测试，但现有快照全量哈希
> 失败、仓库尚无 Git 版本基线，且没有一轮由新版账本完整记录的 60 个交易日
> Paper campaign。因此系统会正确拒绝发布，不得视为已获准的自动实盘系统。

## 一、策略原理

### 1.1 为什么是"价格行为 + 趋势跟随"

追求高收益的前提是**抓住大趋势、砍掉小亏损**。价格行为分析提供了对趋势
最直接的定义——市场结构，而趋势跟随的盈利模型（小亏多次 + 大赚几次）
配合严格的风险预算，是长期复利可行性最高的框架之一。

### 1.2 信号体系（全部由价格派生）

| 模块 | 价格行为概念 | 实现 |
|------|-------------|------|
| 趋势结构 | Higher High + Higher Low | 分形法摆动点识别（含 k 根确认滞后，杜绝未来函数），要求最近两个摆动高点、低点同时抬高 |
| 突破入场 | 关键位突破（强者恒强） | 收盘价创出前 55 日最高价新高 |
| 回调入场 | 趋势中的折返 + 拒绝形态 | 回撤 ≥ 1.5 ATR 后出现**看涨吞没**或**锤子线（Pin Bar）** |
| 动量过滤 | 只买正在上涨的东西 | 个股 6 个月涨幅必须为正 |
| 候选排序 | 平滑的趋势才拿得住 | 按**夏普动量**（12-1 个月动量 ÷ 年化波动率）从高到低择优——宽池中原始动量排序总是挑到最极端的板块脉冲，夏普动量偏好平滑趋势（小型固定名单上原始动量略优，可配置） |
| 股票池 | 只在"当时的大盘股"里选 | 默认**标普 500 点时成分股**（信号日当天真实的指数成员）∩ **63 日滚动成交额前 100 名**。两者都只用当时可知的数据，无幸存者偏差、无后见之明 |
| 大盘开关（二值） | 顺水行舟 | SPY 6 个月动量 > 0 才允许开新仓，否则停止开仓、持仓靠止损自然清空。曾试过"三档分级"（复苏期半仓），被 2000–2014 扩展回测证伪后回退（见[被否决的方案](#被实验否决的方案负面结果同样有价值)） |
| 行业分散 | 不与单一板块共存亡 | 同一 GICS 行业最多 3 个持仓——动量排序爱扎堆热门板块（2022 年曾同时抓 3 只能源股被埋），强制分散换取更好的夏普与回撤 |
| 同公司去重 | 一家公司只押一次 | GOOG/GOOGL 等多股别不同时持有（曾合计押上 5% 单一公司风险）。样本内代价 -0.5pp（噪声内），换真实的单一公司风险减半 |
| 金字塔加仓 | 强者恒强，赢冲输缩 | 持仓每浮盈 2 倍初始风险（+2R / +4R）加仓半个风险单位，最多 2 次，把资金集中到已被市场证明正确的趋势上（海龟系统经典组件） |
| 结构止损 | 摆动低点是多头的底线 | 初始止损取"入场价 − 2.5 ATR"与最近摆动低点的较高者 |
| 跟踪止损 | 让利润奔跑 | 吊灯线：入场后最高收盘价 − 4.5 ATR，只上移不下移 |
| 结构破坏离场 | 趋势终结 | 收盘价跌破前 45 日最低价即离场 |

### 1.3 仓位与风险管理（收益的另一半来源）

- **单笔风险预算**：每笔交易从入场价到止损价最多亏损账户权益的 **2.5%**，
  股数 = 权益 × 2.5% ÷ (入场价 − 止损价)。止损近则仓重，止损远则仓轻，
  把每笔交易的美元风险标准化。
- **单仓上限**：单只股票市值 ≤ 权益的 20%。
- **持仓上限**：最多同时持有 10 只股票（大盘开关 1 档时新开仓配额减半）。
- **不加杠杆**：现金不足按现金缩减。
- **闲置现金不闲置**：回测中现金按 13 周美国国债利率（^IRX）逐日计息，
  对应实盘中"现金买入 SGOV/BIL 短债 ETF 或使用券商现金理财"——
  2022 年空仓期与高利率年份，这部分贡献了可观的无风险收益。

### 1.4 交易节奏

日线级别，每个交易日决策一次：
前一交易日收盘后计算信号 → 次日开盘执行。持仓周期通常数周到数月（趋势单）。

### 统计尺子（诚实的不确定性刻画）

单一历史路径的点估计有极强的迷惑性，`reports/metrics.txt` 中随每次回测
自动输出：

- **CAGR 90% 置信区间 [+5.1%, +23.9%]**（block bootstrap，下界视角）——
  SPY 落在区间内，"跑赢大盘"在单一路径上无统计显著性，
  策略的可信优势在**回撤端**（-22.2% vs -33.7%）；
- **利润集中度**：top-10 交易占总利润 104%、最大单笔占 28%，
  剔除头部 1/3/5 笔后年化降至 +11.4%/+8.8%/+6.4%——
  赚大赔小是趋势跟随的本质，但"错过头部交易"的路径风险真实存在；
- **池敏感度（jackknife）**：随机剔除 20% 股票池 × 10 种子 →
  年化均值 -3.2pp（σ=1.7pp）——这是"约 140 只退市股缺失"这一残余
  幸存者偏差影响的量级上界（退市股偏弱势，真实偏差应再打折）；
- **入场信号的边际价值 +7.0pp/年**：把入场换成随机选股
  （其余机制——大盘开关、止损、仓位——完全不变，20 个随机种子）
  均值只有 +6.8%，真实信号 +13.8% 胜过 100% 的随机种子，
  证明价格行为入场有真实信息量，且约一半收益来自风控体系本身；
- **滑点敏感性**：10-20bp 下年化 10-12%，50bp 下仍 +6%——
  策略在现实交易成本下存活，但收益对成本的斜率应在模拟盘中实测校准；
- **归因**：现金利息仅占总盈利 3%；突破入场贡献 64% 交易利润、
  回调入场 36%（两者都值得保留）。

**③ 压力测试（2000–2014 扩展回测，含两轮大熊市）**：
年化约 +1%、最大回撤约 -33%（SPY 同期年化 +4.3%、回撤 -55%）。
其中 **2008 金融危机区间策略回撤仅 -6%**（SPY -52%）——大盘开关 +
止损体系在趋势性熊市中防御出色；2000–2002 震荡下跌市回撤约 -26%
（SPY -48%）。结论：**在失去的十年里系统大致保本、显著抗跌，
但不产生超额收益**——趋势跟随需要趋势，这是它诚实的边界。

几点解读：

- **胜率只有 24.4% 却大幅跑赢**，是趋势跟随的典型形态：平均盈利单
  (+14.5%) 是亏损单 (-4.1%) 的 3.5 倍，配合金字塔加仓放大盈利单权重。
- **诚实数字 vs 回望名单**：把股票池换成人工挑选的 70 只固定名单
  （`universe.mode: static`），同一策略的回测年化会高出约 5~7pp——
  这就是**幸存者偏差 + 选股后见之明的定价**。本 README 把无偏数字
  放在头条；static 模式保留用于快速实验，其数字应视为偏乐观的上界。
- 点时池的残余偏差：795 只历史成分股中 174 只（约 22%，多为退市/被收购
  公司）在 Yahoo 无历史行情、无法参与回测，结果仍略偏乐观，但远好于
  回望式名单（2000–2014 段该缺失率更高，压力测试结论应再打折扣）。

### 被实验否决的方案（负面结果同样有价值）

以下方案均已实现为可配置开关，但消融实验证伪，默认关闭，勿轻易开启：

| 方案 | 实验结果 | 失败机制 |
|------|---------|---------|
| **时间止损**（N 日未达标即离场回收死钱） | 消融 4 变体全为正但无一显著（p>0.2）；walk-forward 逐年折训练窗每折都选中它，样本外 +6.5% 反输给无时间止损的默认 +8.4% | 样本内吸引力不泛化——被它回收的"死钱单"里藏着后来起飞的慢热赢家 |
| **逐年参数再优化**（walk-forward 网格自选） | 拼接 OOS +6.5% vs 固定默认参数 +8.4% | 训练窗永远偏爱样本内最优的激进组合；参数稳定性胜过优化 |
| **结构化重开**（SPY 创 55 日新高即恢复开仓） | 2015-25 仅 +0.17pp（p=0.95）；2000-02 回撤 -26%→-30.4%、2008 从 -6.4%→-10.8% | "熊市反弹到不了前 55 日高点"的假设不成立——2001/2008 的反弹恰恰能摸到，重开后接飞刀 |
| **内包线突破第三触发**（复用已实现的 inside_bar） | -1.9pp，仅新增 9 笔边际交易 | 内包线突破日与吞没/锤子日高度重叠，边际信号少且质量更低 |
| **熊市做空模块**（档位 0 时做空破位股，风控镜像） | 2015-2025 空头净亏 $7.7 万、年化 -4.5pp；连 2000-2014（两轮大熊市！）空头也净亏、总回撤翻倍至 -62.5% | 跌破 55 日低点时行情已走完大半；熊市反弹又快又狠，专门轧空突破型空头；盈亏比天然不对称 |
| **三档分级大盘开关**（复苏期半仓入场） | 2000-02 回撤从 -26.8% 恶化到 -47.4%、2008 从 -6.8% 到 -20.4%；2015-2025 也无优势 | 熊市中的 V 型反弹信号与真正的复苏无法用 3 个月动量区分，半仓入场就是反复接飞刀 |
| **SPY 底仓**（闲置仓位买大盘 β） | 收益不升（14.6%→13.6~14.7%）、回撤加深 2~3pt | 闲置现金本就吃着 ^IRX 利息且被策略机会性调用，换成 SPY 只添了 β 回撤 |
| 波动率目标杠杆（8 个参数变体） | 全部劣于无杠杆：年化 -2~-6pp、回撤更深 | 本系统暴露已由大盘开关和止损内生调节；已实现波动率缩放恰好在主升段（波动上升期）压仓、平静期（波动爆发前夜）加满，方向反了 |
| 财报回避（入场前 3 天有财报则跳过） | 年化 -2.8pp | 突破信号常在财报前后出现，回避财报等于系统性砍掉最强的一批入场 |
| 相对动量过滤（须跑赢 SPY 才入场） | 年化 -1~-3pp，回撤更深 | 过滤掉了大量处于自身趋势早期的合格标的 |
| 持仓上限 10 → 12 | 与金字塔加仓组合时年化下降 | 资金摊薄与"集中到赢家"的金字塔逻辑互斥 |
| 每行业 ≤2（过紧的行业约束） | 年化 -2.7pp | 好行业里的多个独立趋势被误杀（≤3 是最优：收益持平、夏普/回撤改善，已采纳） |
| 放宽/移除 45 日通道离场 | 放宽 90 日 +0.86pp（p=0.58）、移除 +0.60pp（p=0.75），均不显著；移除使回撤加深 1.8pt | 通道离场账面净亏 $1.5 万是"灾难保险的保费"——按默认保守原则维持 45 日 |
| **周线多时间框架确认**（周线 HH+HL 门控日线入场） | **-6.4pp，p=0.03，CI 全负**（统计显著有害）；2000-14 回撤 -36%→-44% | 周线摆动结构确认太慢（2 周滞后+结构形成需数月），滤掉的恰是趋势早期的最佳入场 |

以上模块的代码全部保留（config.yaml 中有对应开关与实验结论注释），
但除"每行业 ≤3"与"同公司去重"外默认全部关闭。

**消融决策规则**（写进项目文化）：所有 A/B 对比必须在同一数据快照上跑
`paired_test` 配对显著性检验（`pabot/backtest/stats.py`）——
p < 0.10 且 |年化差| ≥ 0.5pp 才可采纳；不可区分时按"简单优先/默认保守"
处理。"疑似有用但不显著"的改动（如时间止损）交给 walk-forward
训练窗自选、样本外裁决。正确性/风险修复（别名映射、僵尸清算、去重）
按其本身性质采纳，不以收益论英雄。

## 四、快速开始

### 4.1 环境准备

```bash
# 需要 Python >= 3.10
uv sync                         # 推荐：严格按 uv.lock 创建/同步环境
source .venv/bin/activate

# 没有 uv 时可回退（不具备 lock 的逐版本复现保证）
# python3 -m venv .venv && source .venv/bin/activate
# pip install -r requirements.txt
```

### 4.2 下载历史数据

```bash
python main.py download          # 默认点时模式：约 800 只（含退市代码），首次约 5 分钟
python main.py download --force  # 强制刷新缓存
```

点时成分股表（fja05680/sp500 开源项目维护）与个股行情都会缓存到
`data_cache/`；已确认无数据的退市代码会写入空标记文件，不再重复请求。

### 4.3 运行回测（2015–2025）

```bash
python main.py backtest
```

终端会打印策略与 SPY 基准的对比指标（含 bootstrap 置信区间与利润集中度），
图表与交易明细输出到 `reports/`。

**数据快照（实验强制）**：yfinance 复权价格会随刷新漂移，
做任何参数实验前先冻结数据并做全量哈希校验：

```bash
python main.py snapshot         # 原子创建、全量自校验并只读发布快照
# 设置 data.snapshot；实验入口还会逐文件验 SHA-256，成功后才具备复现资格
python main.py policy-check     # 检查生产政策、配置哈希与源码身份
```

> 当前 `20260726/20260727` 是缺少 `manifest_version` 的旧格式；即使按 v1
> 解读，二者 `sectors.json` 的清单哈希均为 `aef71b…f87f`，实际均为
> `3459c9…6528`。它们只能解释旧结果，不能用于回测、新实验或发布。应从
> 可信缓存重建快照，不能补写旧 manifest 或关闭校验。

快照消费覆盖行情、行业、财报和点时成员数据；缺少必需附属缓存时明确拒绝，
不会联网补齐或重写快照。目录解析使用配置副本，回测和 Paper 刷新行情后，
原配置及其哈希保持不变。

> 注意：缓存命中时不会重新下载数据。如果修改了 `config.yaml` 中的
> 数据区间，需要先取消 snapshot 配置再 `python main.py download --force`。

### 4.4 模拟盘绩效跟踪（上线后）

点时池的每日交易先刷新 SPY，按最后一根完整日线确定信号日，再加载该日
成分股和账户实际持仓。已退出指数的持仓仍纳入止损检查；基准和利率序列
单独保留。研究下载、回测和 Walk-forward 仍使用完整历史成员池。

Runner 每日把运行、价格行为决策、候选拒绝、订单、成交、持仓变化和权益
写入按模式与匿名账户分区的只追加账本；同时保留权益与滑点 CSV 作为
兼容导出。使用默认路径配置时，实际文件为：

| 内容 | 实际路径 |
| --- | --- |
| 策略状态与锁 | `runtime/<mode>/<账户SHA256>/live_state.json` 及同目录锁文件 |
| SQLite 账本 | `logs/runtime/<mode>/<账户SHA256>/trading_journal.sqlite` |
| 权益、成交 CSV 和报告 | 上述账本同目录；中文日报位于其 `review/` 子目录 |
| 运行行情缓存 | `data_cache_live/runtime/<mode>/<账户SHA256>/` |
| 本地模拟券商状态 | sim 策略状态同目录的 `sim_broker_state.json` |

自定义配置的状态和账本父目录也会追加相同分区，配置内容本身不会被改写。
`dry-run`、`sim`、`paper`、`live` 互不共享状态。随时运行：

```bash
python main.py review --mode sim   # 最近交易日中文事实复盘
python main.py review --mode paper --date 2026-09-11
python main.py report --mode sim
python main.py reconcile --mode sim
```

`report` 在不足 5 个不同交易日的权益记录时，直接从已有权益与成交 CSV
生成报告并说明样本不足，省去行情补数、行业查询和影子回测。达到 5 天后
才准备同期比较，最终仍要求至少 5 个重叠交易日。

输出：累计收益、**实测滑点分布 vs 回测假设 5bp**（显著更差时提示上调
回测滑点重新校准预期）、**实际 vs 影子回测同期对比**与跟踪误差——
普通 `paper` 运行可用于联调，但只有绑定冻结 campaign、账户指纹和实际执行日，
且独立 `paper-close` 在当天实际收盘后采集的持仓/工作订单/账户三类对账均为 `MATCH`，才计入正式 Paper
天数。旧版账本不会被追认为合格证据。参数调整流程见
[`docs/review-adjustment.md`](docs/review-adjustment.md)，系统不会根据单日
盈亏自动改参数。

省略 `--mode` 时按 `broker.paper` 选择 paper/live；离线报告遇到多个账户时必须
传 `--account-fingerprint`。`reconcile --mode sim` 使用本地模拟券商。独立影子
对账用于研究执行偏差，不能替代正式收盘三类对账。兼容 CSV 仍按信号日标记，
对应的是执行时刻权益；正式收盘权益和采样时刻以 SQLite 为准。

旧版未分区 `live_state.json`、账本或 `sim_broker_state.json` 不会自动迁移：
paper/live/sim 启动会明确拒绝。应先核对账户、未决订单和 checkpoint，再迁移
成套状态与账本；不能删除旧文件后假装空账户。演习使用独立目录。

## 五、模拟盘与实盘

### 5.1 注册 Alpaca 并配置密钥

1. 在 [alpaca.markets](https://alpaca.markets) 免费注册账户；
2. 在控制台生成 **Paper Trading** 的 API Key（模拟盘与实盘密钥是两套，不要混用）；
3. 注入环境变量：

```bash
export ALPACA_API_KEY="你的Key"
export ALPACA_SECRET_KEY="你的Secret"
```

### 5.2 四种运行模式

```bash
python main.py dry-run   # 演习：完整跑一遍每日流程，只打印动作，不下单（无需密钥）
python main.py sim       # 本地模拟盘：无需密钥，真实记账持仓/现金/权益（推荐起点）
python main.py paper     # Alpaca Paper 联调；正式取证需额外传 --campaign
python main.py live --confirm-live  # 实盘；同时要求 broker.paper: false
```

**还没有 Alpaca 密钥？** 直接用 `sim` 启动每日 cron——本地模拟券商
（`sim_broker_state.json` 持久化记账，最新行情价 ±5bp 撮合）会让完整
流程真实跑起来并开始积累 `report` 所需的权益与滑点数据；
拿到密钥后可另行启动 Paper；账户、状态和证据独立，Sim 的持仓与天数不转入 Paper。

模拟盘 → 实盘切换必须同时满足：`broker.paper: false`、实盘 API 密钥、
命令显式带 `--confirm-live`。命令与配置不一致会直接拒绝，不会静默选择
另一账户；live 也不再等待 cron 无法回答的交互输入。**强烈建议先完成
至少 60 个交易日的 Paper 前瞻门禁。**

### 5.3 每日定时运行

Runner 的信号时序是：**用昨日完整 K 线算信号，今日开盘附近执行**。
回测中的盘中止损与 runner 次日检查后的市价卖出仍有成交时点差异，parity 仅验证决策。
用 cron 在每个交易日美东时间 09:35（北京时间夏令 21:35 / 冬令 22:35）触发一次：

```bash
# crontab -e （完整样例见 scripts/crontab.example，含对账、绩效与复盘任务）
35 9 * * 1-5  cd /path/to/PABot && .venv/bin/python main.py sim >> logs/live.log 2>&1
#                                    拿到密钥后把 sim 换成 ↑ paper
```

Runner 每次运行会：

1. 强制刷新行情，取**最近一个已收盘交易日**的完整日线
   （按美东时间自动剔除盘中未走完的半根 K 线，本机在任何时区运行都安全）；
2. 检查持仓：昨日盘中触及止损 或 收盘跌破离场通道 → 市价卖出，
   并**等待卖单成交、资金到账后**才进行任何买入（避免购买力竞态）；
3. 金字塔加仓：持仓浮盈达标 → 按半个风险单位市价加仓；
4. 扫描信号：突破 / 回调触发 → 先取实时报价做**跳空保护**
   （现价已低于止损直接放弃，与回测逻辑一致），再按风险预算市价买入；
5. 所有买卖在调用券商前先落价格行为证据与确定性客户端订单号，成交后
   追加订单终态、成交和持仓事件；
6. 上移吊灯跟踪止损，把状态和执行时刻权益写入该模式/账户的状态文件和
   SQLite 只追加账本。正式 Paper 还需独立执行收盘采集。

持仓股数以券商为准；`live_state.json` 只保存券商没有的信息
（止损价、初始风险 R、已加仓次数、方向等）。在不存在未决/外部订单时可按
券商持仓重建；一旦订单事实不明确，系统会冻结而不是猜测性重建。
Yahoo 与 Alpaca 的代码格式差异（`BRK-B` vs `BRK.B`）由 broker 层自动转换。

**闲置现金**：回测假设现金按短债利率计息。实盘对应做法是把长期闲置现金
手动买入 SGOV / BIL 等短债 ETF（系统不会自动做这件事，避免和开仓资金
抢流动性），或直接使用券商的现金理财功能。

### 5.4 运维保障（内置）

| 机制 | 行为 |
|------|------|
| 交易日检查 | 假日 / 周末 / 盘外 cron 触发时自动跳过，不误动作 |
| 当日幂等性 | 同一信号基准日只执行一次，cron 重复触发 / 手滑重跑不会重复下单；人工补跑用 `--force` |
| 进程文件锁 | 两个实例并发运行时后者直接退出并告警（防双重下单） |
| 跨进程订单幂等 | 下单前先持久化 `planned` 事件并生成稳定 `client_order_id`；Alpaca/SimBroker 重启后先查已有订单，提交响应未知时只读恢复、不猜测性重发 |
| 启动恢复门禁 | 进程锁之后、行情刷新和任何下单之前，只读核对账本未决订单、券商全部工作订单及本地状态 SHA-256。状态指纹使用 SQLite 单调序号，不依赖可能回拨的系统时钟；`planned/submitted/uncertain/partial/dead`、旧版无指纹交接、状态文件回滚、外部订单或读取失败均 HOLD |
| 订单结算闭环 | 每笔订单等待终态；**超时先请求撤单，再按 client ID 复核**。撤单请求成功不等于订单已终止；只有券商明确返回终态才关闭。部分成交或未知状态立即进入恢复冻结。卖单失败保留原止损、买单失败不写幽灵持仓、离场失败持仓当日禁止加仓 |
| 证据账本 | 配置/源码/数据哈希、候选拒绝、订单、成交、持仓和权益只追加写入；相同幂等键内容漂移会失败，事实表禁止 UPDATE/DELETE |
| 数据熔断 | 信号基准日距今超 4 天（数据源故障）→ 整体熔断不交易并告警；持仓股数据缺失 → 单独列出告警 |
| 拆股侦测 | 券商股数突变且**持仓均价同比例反向变化**（拆股特征交叉验证）→ 价格状态按比例缩放；股数突变但价格不符（订单晚成交/手工操作）→ 冻结该标的当日决策并告警，绝不盲目缩放止损 |
| 状态文件加固 | 文件 fsync → 原子替换 → 目录 fsync，并把最终 SHA-256 与订单交接在同一 SQLite 事务写入单调 checkpoint；任一步失败都不宣称完成。每日备份到 `state_backups/`，恢复旧备份会在下次启动被识别 |
| 异常告警 | 运行抛出任何异常都会先推送 webhook 告警再退出 |
| 日终摘要 | 每次运行结束推送当日动作清单（离场/入场/加仓）与账户快照 |
| 死人开关 | 每次成功运行 ping 外部心跳服务（`PABOT_HEARTBEAT_URL`，如 healthchecks.io），连续缺 ping 由外部服务告警——系统停摆时它自己发不出告警，必须靠外部侦测 |

**通知配置**（可选）：设置环境变量后自动启用，飞书自定义机器人与
通用 JSON webhook（Slack 兼容）按 URL 自动识别：

```bash
export PABOT_WEBHOOK_URL="https://open.feishu.cn/open-apis/bot/v2/hook/xxx"
export PABOT_HEARTBEAT_URL="https://hc-ping.com/<uuid>"   # 死人开关（可选）
```

**部署方式与数据源升级的评估**见 `docs/decisions.md`
（笔记本 cron → VPS 迁移清单、Norgate/EODHD 对比调研）。

### 5.5 严格影子对账（建议每日或至少每周）

```bash
python main.py reconcile
```

命令会强制刷新独立实盘缓存，用与生产相同的策略回测到最近完整数据日，
逐标的比较理论与券商的**存在性、方向和准确股数**。券商、网络、行情或
回测不可用时结果是 `UNKNOWN`，绝不回退本地状态制造“完全一致”；结构化
结果同时写入复盘账本。`UNKNOWN` 和 `DRIFT` 都需要人工处理。

### 5.6 复盘与受控调整

```bash
python main.py review
python main.py policy-check
```

调整必须经过“预注册单变量假设 → 同快照配对实验 → Walk-forward/压力/
测试 → Shadow → Paper 至少 60 个交易日 → 人工批准”。实验与发布门禁
只生成证据，不会自动修改生产配置。候选包会精确冻结候选配置、回滚配置、
原始实验、源码和快照身份；目录不可覆盖，验证时重新计算所有哈希。完整制度见
[`docs/review-adjustment.md`](docs/review-adjustment.md)。

正式 Paper 取证使用冻结 campaign：

```bash
python main.py paper-account-fingerprint
# trading-dates.json 必须来自权威 NYSE 交易日历，并经人工复核；格式见下方
python main.py paper-campaign-init \
  --config reports/governance/candidates/<candidate-config-hash>/candidate.config.json \
  --campaign-id pa-breakout-60-v1 \
  --account-fingerprint <上一步输出的匿名SHA256> \
  --trading-dates trading-dates.json
python main.py paper \
  --config reports/governance/candidates/<candidate-config-hash>/candidate.config.json \
  --campaign reports/governance/paper/pa-breakout-60-v1.json
# 当天实际收盘后运行；使用同一候选配置和 campaign
python main.py paper-close \
  --config reports/governance/candidates/<candidate-config-hash>/candidate.config.json \
  --campaign reports/governance/paper/pa-breakout-60-v1.json
python main.py paper-audit \
  --config reports/governance/candidates/<candidate-config-hash>/candidate.config.json \
  --campaign reports/governance/paper/pa-breakout-60-v1.json
```

`trading-dates.json` 冻结每个实际执行日及其精确的信号日，且后一项的
`signal_date` 必须等于前一项的 `execution_date`：

```json
[
  {"execution_date": "2026-08-10", "signal_date": "2026-08-07"},
  {"execution_date": "2026-08-11", "signal_date": "2026-08-10"}
]
```

`paper-campaign-init` 只冻结身份和预期日期，不会连接交易、更改配置或启动任务；
正式 campaign 必须显式使用候选包内的 `candidate.config.json`，不能误用当前
基线 `config.yaml`。
每次运行必须匹配 campaign 完整哈希、候选配置、源码、匿名账户、预期执行日
和精确信号日；正式 campaign 禁止 `--force`。末尾连续 60 个合格交易日才
通过，不能从历史记录挑日拼接。

开盘执行从 Alpaca calendar 读取当日开收盘时刻及上一个真实交易日，写入账本并
校验冻结的信号日。`paper-close` 再次核对该会话、账户、配置、源码与状态指纹，
只读采集账户/持仓/工作订单，以一个事务写入权益和三类对账。采样与账本写入
都必须处于同一交易日的实际收盘之后，支持提前收市；次日不得补录，`--date`
和 `--force` 均不可绕过。这里记录的是收盘后的实际账户快照，并非交易所官方收盘价。
重复采集返回首次结果，不覆盖 UNKNOWN/DRIFT；写入中途失败则整个事务回滚。
旧证据缺少会话和时间字段时不计入正式天数。

## 七、回测方法论与已知局限

**做对了的事（可信度来源）：**

- **无未来函数**：摆动点带 k 根确认滞后；突破通道 `shift(1)`；
  信号用第 T 天收盘后的完整 K 线计算，成交发生在 T+1 开盘。
- **真实撮合**：次日开盘价成交 + 单边 5bp 滑点；盘中止损按"跳空取开盘价、
  否则取止损价"的保守模型成交。
- **前复权数据**：分红拆股不会造成假突破。注意这意味着策略收益**隐含了
  股息再投资**（SPY 基准同样按前复权处理，对比是公平的）。
- **组合级回测**：现金约束、持仓上限、信号竞争排序、金字塔加仓的
  资金占用全部如实模拟。
- **数据快照**：正式实验必须固定快照并逐文件校验 SHA-256；清单一致但
  内容漂移也会拒绝。新快照先在同文件系统临时目录中完整复制、自校验、
  同步，再原子改名并设为只读；失败不会留下半成品。实盘刷新写独立缓存目录。
- **统计尺子**：bootstrap 置信区间 + 配对显著性检验 + 利润集中度
  随每次回测自动输出；消融采纳有明确的显著性与效应量门槛。
- **随机入场基线**：入场信号的边际价值（+7pp/年）经零假设对照量化，
  不是"信号看起来有用"。
- **测试护栏**：无未来函数属性测试、引擎黄金样例（撮合价格与资金守恒
  逐位断言）、MockBroker 失败路径、快慢路径等价性、
  **回测↔实盘决策一致性（parity）**、账本幂等、崩溃恢复、严格对账、
  治理契约与发布门禁。
- **证据与调整治理**：每次生产决策绑定价格行为证据；参数只允许通过
  预注册单变量实验提出候选，离线结果不会自动覆盖生产配置。
- **对抗性验证**：四视角（引擎/实盘/数据/统计）多代理审查全部核心代码，
  13 个候选缺陷中 11 个确认属实并全部修复（含快照被静默写入、
  订单超时不撤单、拆股误判缩放止损等实盘级隐患）。
- **三层验证**：样本内回测之外，另有 walk-forward 样本外验证
  （2019–2025 逐年折拼接 OOS）与 2000–2014 跨时代压力测试
  （含两轮大熊市），三层数字全部公开在第二节，未择优展示。

**已知局限（阅读结果时请记住）：**

1. **残余幸存者偏差**：默认的点时成分股模式已消除**选股层面**的
   幸存者偏差（只能买当天真实在指数里的股票），但历史成分股中
   约 140 只已退市公司在 Yahoo 无历史行情、无法参与回测——"死掉的公司缺席"
   使结果仍略偏乐观。static 固定名单模式的偏差要大得多（同一策略
   年化虚高约 5~7 个百分点），其结果只应视为上界。
2. **2024–2026 并购潮造成的近期数据损失（已尽力修复）**：一批近年
   仍在指数中的公司因被收购/私有化退市（HES/PXD/MRO/DFS/WBA/JNPR/
   ANSS/CTLT/K/CMA/IPG/HOLX/DAY/CTRA 等约 14 只），Yahoo 随退市
   **删除了它们的全部历史行情**——它们在 2013–2025 的大部分时间里
   本是可交易成员，如今永久缺席，属于免费数据源的固有损耗。
   已修复的部分：改码存续的公司通过别名恢复完整谱系
   （MMC→MRSH、BK→BNY、PARA→PSKY、FI→FISV、NLOK→GEN 等 35 组）；
   FBIN/DINO 的谱系从历史快照中抢救保留。实测：恢复的候选加入后
   基线逐位不变（低动量名字从未赢得排序进场），损失的量级参照
   统计尺子的 jackknife 上界。根治方案见 `docs/decisions.md` 决策一
   （付费数据源）。
3. **参数过拟合风险**：55/45 通道、2.5/4.5 ATR 等参数以趋势跟随领域的
   经典取值为起点，在 2015–2025 同一段历史上做过多轮比较与邻域稳健性
   验证后选定——这意味着展示的结果**必然含有拟合成分**。好消息是
   逐年折 walk-forward 显示固定默认参数在样本外胜过逐年再优化
   （+8.4% vs +6.5%），参数面确实平坦；坏消息是逐年 OOS 离散度
   巨大（-8%~+22%），单一年份的预期应极为保守。
4. **日线粒度**：盘中止损成交价基于日线高低价近似，无法模拟盘中先后顺序
   （同日先触止损再创新高时按止损处理，属保守假设）。
5. **过去 ≠ 未来**：2015–2025 是美股（尤其科技股）的长牛区间，
   趋势策略天然受益；换一个十年结果可能显著不同——2000–2014
   压力测试（年化 +1%）就是这句话的实证。
6. **当前快照不能支撑新结论**：两份旧快照缺少新版 manifest 版本字段，且
   `sectors.json` 与清单哈希不一致。历史数字保留作旧基线说明，但在重建
   可信快照并重跑之前，不得把任何新参数收益差解释为已验证改进。
7. **尚未形成生产版本基线**：仓库当前没有 Git commit/remote，也尚未
   累积由新版 campaign 绑定并审计通过的 60 个交易日 Paper 前瞻证据。
   历史账本因缺少 attempt/campaign/account 身份不会被追认为合格天数。
8. **恢复处置仍需人工**：系统已经能在未知订单、部分成交、外部工作订单或
   成交后状态未交接时可靠冻结，但不会猜测性修复。当前没有自动“解除 HOLD”
   命令；必须先在券商与账本中人工判明事实，再开发受审计的处置流程。
9. **交易日历仍是外部证据**：campaign 会严格执行并审计冻结日期，但不会
   自行证明输入文件来自 NYSE。正式取证前必须从权威日历导出并人工复核。
10. **前瞻产物尚未形成原始证据包**：当前发布门禁会只读重验候选包、源码、
    完整快照和 Paper SQLite 原始账本，也会以候选包内假设与实验契约为唯一来源；
    但 Walk-forward、压力测试、完整测试和 Shadow 尚未绑定各自不可覆盖的原始
    产物。候选包会明确 `forward_evidence_verified=false`，发布门禁必定拒绝，
    因此现阶段只能生成候选审计包，不能宣称已有可信发布授权。

## 八、风险提示

本项目仅供学习与研究。任何交易系统都无法保证盈利，历史回测收益
**不代表**未来表现。实盘交易可能损失全部本金，请务必：

1. 先用 Paper 验证至少 60 个交易日；
2. 只投入亏得起的资金；
3. 理解每一行做出买卖决策的代码之后再启用实盘。
