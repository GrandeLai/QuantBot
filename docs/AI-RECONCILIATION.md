# 回测账目只读核验

使用本地逐步日志，从成交和公司行动重新计算现金、持仓、平均成本、已实现/未实现损益、累计估计成本、分红应收、分红权益、账户权益和回撤，逐时点比对记录。此过程不调用模型、行情接口或交易执行器，也不创建运行账户。

```bash
quantbot runtime replay-show /absolute/path/to/candidate.jsonl --reconcile
```

基础回测报告的 `candidate.journal_path`、`baseline.journal_path` 指向对应日志；研究和滚动评估的各窗口也提供日志路径。需要保留这些本地日志，成功回测下载的单个 JSON 报告不能代替 `.jsonl` 文件。

输出 `accounting.status`：

- `reconciled`：现有记录的账目一致，返回重算期末余额。
- `mismatch`：数值或持仓不一致，列出发生时点、字段、预期值和记录值。
- `unavailable`：没有账户记录，或旧日志缺少估值价格，不能完成核验。

重复成交身份、卖出超仓、现金透支、非整数美股成交及无效数值会明确报错。成交价已经包含估计成本，核验时不重复扣费。金额计算使用 Decimal；比对报告的浮点字段时允许绝对 `1e-8` 或相对 `1e-15` 中较大的表示误差。

公司行动以日志开头冻结的来源为依据，独立重算拆股股数与总成本、除息日前持仓的分红权益、支付现金；不调用执行器的公司行动实现。缺失/重复行动、与来源不一致、提前支付和事件时间越界会被拒绝。待到账分红计入权益，不计入可用现金。分红单列为 `dividend_income`，不并入股票交易的已实现损益。旧日志未声明公司行动时，仍可按原字段核验。

仅当运行完整且账目核验一致时，命令返回 0；不完整、无法核验或不一致时返回 2。中断日志的已存部分可以账目一致，但不能因此把运行改判完成。旧日志保持原样，需要重新回测才能补齐估值价格。

这项检查核对记录内部的数学一致性，不认证行情来源、成交真实性、市场容量、期权账户或收益有效性，也不替代券商对账。

## 可复现验收

```bash
.venv/bin/python docs/examples/validate_reconciliation.py \
  --output runs/reconciliation-validation-new
```

样例分别运行美股与加密规则回测，核验策略和对照共四份日志；每份 30 个账户时点。另存一份故意将初始空仓改成期末持仓的损坏样例，核验应指出首个时点的持仓差异。原日志不改写，输出目录不能复用。全部使用合成行情，网络、真实模型和券商调用为 0。
